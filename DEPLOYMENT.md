# Omega's Kitchen — Standalone APK & Deployment Runbook

A standalone APK runs without your PC, so the backend must live online. Three phases.
Steps marked **[you]** need a login/password I can't do for you; everything else is already scaffolded in this repo.

---

## Phase 1 — Database (MongoDB Atlas, free)

1. **[you]** Create a free account at https://www.mongodb.com/cloud/atlas and a free **M0** cluster.
2. **[you]** Database Access → add a user (username + password).
3. **[you]** Network Access → add IP `0.0.0.0/0` (allow from anywhere; the host's IP is dynamic).
4. **[you]** Connect → Drivers → copy the connection string. It looks like:
   `mongodb+srv://USER:PASSWORD@cluster0.xxxxx.mongodb.net/?retryWrites=true&w=majority`
   Keep it for Phase 2.

## Phase 2 — Backend host (Render, free)

The repo already contains [`render.yaml`](render.yaml) (native Python) and [`backend/Dockerfile`](backend/Dockerfile) (any Docker host).

1. **[you]** Push this project to a GitHub repo (Render deploys from Git).
2. **[you]** At https://render.com → **New + → Blueprint** → connect the repo. Render reads `render.yaml`.
3. **[you]** When prompted, fill the secret env vars:
   - `MONGO_URL` = the Atlas string from Phase 1
   - `ADMIN_EMAIL` = your admin email
   - `ADMIN_PASSWORD` = a **strong** password (the dev one `OmegaAdmin2026!` is public in history — change it)
   - `JWT_SECRET` is auto-generated by Render.
4. Deploy. You'll get a public URL like `https://omega-kitchen-api.onrender.com`.
5. Verify: open `https://<your-url>/api/auth/login` — a JSON error (405/422) means it's live.

   > Free Render services sleep after inactivity and take ~30s to wake on the first request. Fine for testing; upgrade for production.

See [`backend/.env.production.example`](backend/.env.production.example) for the full env list (incl. optional Gmail reset creds).

## Phase 3 — Build the APK (EAS, free)

The repo already contains [`frontend/eas.json`](frontend/eas.json) and an Android package name in `app.json`.

1. In [`frontend/eas.json`](frontend/eas.json), replace `REPLACE-WITH-YOUR-DEPLOYED-API.onrender.com` (in both `preview` and `production`) with your Render URL from Phase 2.
2. **[you]** Create a free Expo account at https://expo.dev.
3. From `frontend/`:
   ```bash
   npm install -g eas-cli      # one time
   eas login                   # [you] — your Expo credentials
   eas build -p android --profile preview
   ```
4. EAS builds in the cloud (~10–20 min) and gives you a download link for the **APK**. Install it on any Android phone — it talks to your deployed backend, no PC required.

   > `preview` builds a real native app (no Expo Go, no keyboard-controller stub). For Play Store, use `--profile production` (App Bundle) + `eas submit`.

---

## Security before going public
- Rotate `JWT_SECRET` and `ADMIN_PASSWORD` to fresh values (don't reuse the dev ones in git).
- Keep `0.0.0.0/0` on Atlas only if the DB user password is strong; otherwise restrict to the host's egress IPs.
- `backend/.env` (dev secrets) is for local only — never deploy it; the host injects env vars instead.

## Local dev (unchanged)
Mongo on `:27017`, backend `uvicorn server:app --host 0.0.0.0 --port 8001`, frontend `npx expo start`.
For Expo Go on a phone, set `EXPO_PUBLIC_BACKEND_URL` in `frontend/.env` to your PC's current LAN IP.
